# A project's board, step 3: review steps — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workflow step of a new kind, `review`, is an approval played by an agent: in a session
of its own it judges an earlier step's work and either approves it or sends it back with a note,
through an onehand tool, never read from prose.

**Architecture:** `StepKind::Review` runs like an agent step (its own lane, a prompt, a turn) but is
judged by a **verdict** instead of gates. The verdict arrives through a new onehand tool,
`review_verdict`, which the carrier hands to the run's drive as an input; the drive holds it and
the run judges it when the review's turn ends: approve → next step; send back → a miss and a new
visit to `on_reject` with the note; no verdict → a miss and a carry-on prompt. Rules stay in core
(`Run`, `RunDrive`); the app only routes the tool call to the run whose session called it.

**Tech Stack:** Rust, GPUI + gpui-component, serde/toml.

**Spec:** `docs/superpowers/specs/2026-11-24-board-design.md` (*Review steps*)

## Decisions made here

- **TOML shape:**
  ```toml
  [[steps]]
  id = "review"
  label = "Review"
  kind = "review"
  of = "implement"          # an earlier agent step
  on_reject = "implement"   # optional, defaults to `of`; an earlier agent step
  agent = "Claude"          # optional, defaults to the run's agent
  prompt = "Review the change …"
  mode = "…"                # optional, as an agent step's
  options = { model = "strong" }   # optional
  ```
  A file with a review step is written as `schema_version = 2`.
- **A review step always has a lane of its own**, named for it, whether it names an agent or
  not, so the reviewer never judges in the session that wrote the work.
- **The verdict is held until the review's turn ends**, then judged; the last verdict of the turn
  counts. A verdict called outside a visit to a review step, or from a session that is not that
  review's, is refused and changes nothing.
- **Send back is a miss** and fills `{revise}` in `on_reject`'s prompt. When the prompt does not
  name `{revise}`, the note is added as `<review label> asked for changes:\n\n> <note>` (a
  person's Revise keeps `A person asked for changes:`), followed by the step's answer before, as
  today.
- **No verdict is a miss** and the review is prompted again with:
  `End your review by calling review_verdict: approve, or send back with a note.`
- **The review's own answer is kept** as `{output.<review id>}` (a later step can read it).
- **A review step is not an approval:** the run's budget runs while it works, the Tasks page shows
  it at work, and *Continue*/*Revise* do not apply to it. A person can still take over or Stop.
- **The tool is listed from the start:** a review lane's session is granted `review_verdict` (with
  the task's own tools, if any) before its agent connects, so an agent that lists tools once sees
  it. A session switched on (*Agent controls onehand*) lists it too; it is refused there unless
  that session is a review's, at its review.
- **Tool words:**
  - input `{ "verdict": "approve" | "send_back", "note": string }` (`note` required for `send_back`, non-empty)
  - answer: `Approved. The review ends when this turn does.` / `Sent back to <on_reject label>. The review ends when this turn does.`
  - refused: `No review is waiting on this session.` / `A send back needs a note saying what to change.`

## Global Constraints

- Core GUI-free; rules in core; the app carries effects only (`docs/drives.md`). Exhaustive matches,
  no wildcards. Nothing in core `pub` unless named outside. Comments never cite documents.
- Workflows without a review step behave and save exactly as before; every existing test passes.
- Validation words (exact):
  - empty `of`: `it reviews no step yet: name an earlier agent step in of`
  - `of` not an earlier agent step: `of names <of>, which is no earlier agent step`
  - `on_reject` not an earlier agent step: `on_reject names <id>, which is no earlier agent step`
  - empty prompt: the agent step's existing empty-prompt words
- `workflow/run.rs` is at 797 lines: put the review's judging in a new `workflow/run/review.rs`.
  `core/control/drive.rs` (713) and `app/control.rs` (653): keep additions small or in new files.
- Amend the rule "No tool answers a card, a permission or an approval" (core `control.rs` module
  doc, `docs/control.md`) to say the one exception: `review_verdict` answers only the review asked
  of the calling session itself.
- `make fmt`, `make clippy CLIPPY_EXTRA="-- -D warnings"`, `cargo test` before each commit. Known
  parallel flakes that pass alone: `deleting_removes_the_folder_after_the_window_closes`,
  `a_window_closing_writes_the_waiting_burst`, onehand-issues `only_the_newest_write_moves_the_selection`.

## Review Focus

1. **A reviewer and a developer that never agree** → each send back is a miss; past the workflow's
   `misses` the run ends exhausted at the review step. (Test in Task 2.)
2. **The reviewer calls the tool, then keeps talking and calls it again** → the last verdict of the
   turn counts. (Test in Task 2.)
3. **The tool called by the developer's session, or after the review's turn ended** → refused,
   nothing changes. (Tests in Tasks 2 and 3.)
4. **A send back without a note** → refused by the tool with its words; the turn can still call it
   properly. (Test in Task 3.)
5. **An agent that lists tools once, at connect** → sees `review_verdict` in its first
   `tools/list`. (Test in Task 3.)

### Task 2: The engine judges a review by its verdict

(a review stands at work). Tests: `workflow/tests.rs`, `task/drive/tests.rs`.

**Interfaces:**
- Consumes: Task 1.
- Produces:
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq)]
  pub enum Verdict { Approve, SendBack(String) }
  impl Run { pub(crate) fn reviewed(&mut self, verdict: Option<Verdict>, answer: &str, now: u64) -> Action }
  impl RunDrive { pub fn verdict(&mut self, lane: &Lane, verdict: Verdict) -> Result<String, String> }
  impl Joined<'_> { pub fn verdict(&mut self, lane: &Lane, verdict: Verdict) -> Result<String, String> }
  ```
  `RunDrive::verdict` accepts only while the run awaits the turn of a review step whose lane is
  `lane`; it stores the verdict (replacing an earlier one) and answers the tool words above;
  otherwise `Err("No review is waiting on this session.")`. The held verdict is cleared on every
  new visit.
- `Run::reviewed`: keeps the answer as `outputs[review id]`; `Some(Approve)` → `enter(step+1, "approved by <label>")`;
  `Some(SendBack(note))` → `miss(...)` (exhausting as any miss), else `revise = Some(note)`,
  `revise_by = Some(<label>)`, `enter(on_reject, "sent back by <label>")`; `None` → `miss(...)`, else
  prompt again with the carry-on words above.
