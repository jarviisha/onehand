# Board step 2: entries name the tasks — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** What is on a board is what its entries name, not what the tasks say: a start is
written before it is asked, a stop keeps the issue in its column, a task can be removed from the
board, and the tasks the board holds are never capped or dismissed.

**Architecture:** `board.toml` goes to `schema_version = 2`. Its work column and Done hold entries
naming tasks. A version-1 file adopts the board's tasks once, when the tasks are first read.
`BoardDrive` writes an entry, and asks for its start only once that write is answered. A run's
end moves the entry on. The drive tells `TasksDrive` which tasks it holds (`Effect::Held`). The
page and the counts read the entries.

**Tech Stack:** Rust, serde + toml, GPUI in the app only.

**Spec:** `docs/superpowers/specs/2026-11-27-board-columns.md`, *Step 2*, *The model*, *The drive*.

## Global Constraints

- Core GUI-free. No drive reads the clock or mints an id. Our enums are matched whole. Nothing in core is `pub` that nothing outside it names. No file past 800 lines of code. No comment or string names a document.
- `SCHEMA_VERSION = 2`; a version-1 file is read and upgraded once; `DONE_KEPT = BOARD_SHOWN` (50).
- A new task's run id is its task id.
- Deliberate changes, said in `docs/board.md` and `CHANGELOG.md`:
  - A task off the board (removed, or in Done) that a person retries or resumes is theirs. Its end is not the board's.
  - *No board* deletes the file. Its tasks run on as the person's.
  - A stop leaves the issue in its column.
  - Dismiss is refused on a held task; *Remove from board* takes its place.
- Checks: `cargo test --workspace --locked`, `make clippy CLIPPY_EXTRA="-- -D warnings"`, `make fmt`. Build output stays on `/data`.

## Review Focus

1. **A start's write fails.** The entry is put back to To do and no task starts. The test is in Task 3.
2. **A later change rides past a failed write.** A start held for write 1 is asked once write 2, which carries it, lands; it is asked once only. The test is in Task 3.
3. **The first boot after the upgrade.** A board with a running task, a failed one and a done one: the running and failed tasks land in the work column, the done one in Done, and the cap removes none of them. The tests are in Task 2 and Task 4.
4. **A person retries a task that is in Done, or one removed from the board.** Its end moves nothing on the board and closes nothing. The test is in Task 3.
5. **Stop on a board task.** It stays in its column, still holds its issue out of the Backlog, and its team place frees so To do is looked at again. The tests are in Task 3 and Task 5.

**Interfaces:**
- Produces:
  - `pub const SCHEMA_VERSION: u32 = 2;` and `pub const DONE_KEPT: usize = crate::board::BOARD_SHOWN;`
  - `Board::shape()` accepts version 1 as step 1 knew it, and version 2. Version 2 has the same columns, with work entries each naming a `task` and `run`, and up to `DONE_KEPT` done entries each naming a `task`. Anything else is `Err`.
  - `pub(crate) fn adopts(&self) -> bool`: true for version 1.
  - `pub fn work(&self) -> &[Entry]`: the work column's entries.
  - `pub fn done(&self) -> &[Entry]`: the done entries, newest first.

  - `pub(crate) fn upgraded(&self, work: Vec<Entry>, done: Vec<Entry>) -> Board`: sets version 2, keeps the newest `DONE_KEPT` done entries, and drops from To do any issue that `work` or `done` names.
  - `pub(crate) fn started(&self, issue: u64, task: &str, now: u64) -> Board`: moves the issue from To do to the end of work, as `{ task: Some(task), run: Some(task), since: now }`.
  - `pub(crate) fn finished(&self, task: &str, now: u64) -> Board`: moves the task's work entry to the front of done, capped.
  - `pub(crate) fn removed(&self, issue: u64) -> Board`: removes the issue from every column and from Done.
  - `Board::made` writes version 2.

  - `crates/core/src/board.rs`: `on_board` becomes `pub(crate)`.

**Interfaces:**
- Produces:
  - `pub struct Seen { pub id: String, pub project: ProjectId, pub issue: u64, pub run: Option<String>, pub standing: Option<bool>, pub recency: u64 }`. One per board-origin task. `standing` is `board::on_board`'s answer: `Some(true)` for done, `Some(false)` for on the board, `None` for off it.
  - `pub fn seen(task: &Task, working: Option<Working>) -> Option<Seen>` in `board.rs`, for the carrier.
  - `Input::TasksRead { tasks: Vec<Seen> }`.
  - `Effect::Held { tasks: HashSet<String> }`: the tasks named by entries outside Done, across every board.

**Rules on `TasksRead`:**
- **A board that `adopts()`:** each of its tasks with `Some(false)` becomes a work entry `{ task, run, since: now }`, oldest first by `recency`. Each with `Some(true)` becomes a done entry, newest first. Write `upgraded(…)`.
- **Every board, after that:** drop each work entry whose task is not among `tasks` and is not starting. Its issue goes back to the Backlog. Write if anything changed.
- **Last:** emit `Held` once, with all boards.

### Task 3: The ordered start, a run's end, and removing from the board

**Files:**
- Modify:
  - `crates/core/src/board/drive.rs`.
  - `crates/core/src/board/drive/look.rs`.
  - `crates/core/src/board/drive/look/tests.rs`: tests that assert a `Start` right after a read now land the write first.
- Test: `crates/core/src/board/drive/look/tests.rs`.

**Interfaces:**
- Consumes: Task 1's `started`, `finished`, `removed`; Task 2's `Held`.
- Produces:
  - `BoardWrite` gains `pub seq: u64`, and `Input::Written` gains `seq: u64`. `seq` is a per-drive counter of writes.
  - The held starts: a list in memory of `(project, seq, Effect::Start)`.
  - `Input::Ended { id, issue, task: String, run: Option<String>, outcome }`.
  - The command `remove(&mut self, id: &ProjectId, issue: u64, working: bool) -> Result<Vec<Effect>, String>`. It refuses while `working`, with *Stop it first*.

**Rules:**
- **The look** writes `started(issue, task, now)` for each issue it starts, in the same write as the gone issues. It holds the `Start`s for that write's `seq`.
- **`Written` with `Ok` for `seq` s:** ask every held start whose seq is at most s.
- **`Written` with `Err` for `seq` s:**
  - If a later write was made for the project, re-tag held starts at or below s to the newest seq.
  - Otherwise drop them, and take their issues out of `starting`.
  - `Saves` decides what is put back.
- **`Ended`:** act only when an entry outside Done names `task`.
  - Done: write `finished(task, now)`, and remember the issue for closing.
  - Any other outcome: the entry stays.
  - Then look when `pulls_next(outcome)`.
  - Emit `Held` when an entry moved.
  - An end of a task no entry names does nothing; closing no longer follows a done end of such a task.
- **No closing again at boot**, which the spec asks for an entry in Done whose issue is still
  open: a person may have reopened that issue on purpose, and a boot would close it again. The
  rare crash between the move to Done and the close leaves the issue open, for the person to
  close.
- **`remove`:** write `removed(issue)` and emit `Held`.
- **`unbind`:** also emits `Held`.
