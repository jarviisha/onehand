# Board step 6: the hand-over, the history, and the end of the proposal — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- A column's run can read what the task's previous run answered.
- A task says, in its detail and on the Tasks page, which columns its runs ran in and where it stands on the board.
- The project page's board link counts what waits for a person.
- The proposal's behaviour moves into the owning documents, and the proposal, the spec and the plans are deleted.

**Spec:** `docs/superpowers/specs/2026-11-27-board-columns.md`, *Step 6*; the proposal's *Handing over between columns* and *Across the columns*.

## Decisions (builder's calls, said in the PR)

- **The variable is `{handover}`.**
  - It is filled with the last kept answer of the task's previous run: the output of that run's last visit to an agent step that keeps its answer.
  - It is empty on a first run, and on a run whose previous run kept no answer.
  - `workflow::validate` accepts it in any agent step's prompt and never refuses it as always empty, since a workflow cannot know whether it runs first.
  - It is a variable only. Unlike `instructions`, nothing is added to a prompt that does not name it, so a workflow keeps the prompt its author wrote.
- **The hand-over is kept on the run** (`Run::handover: Option<String>`, serde default, skipped when none).
  - `Task::next_run` sets it.
  - A retry of that run carries it (`Run::retry_of`), so a retried column run reads the same hand-over.
- **Run labels are core's words:**
  - `workflow::Run::label(n)` gives *Run N · <column>*, or *Run N* when no column is kept.
  - The task detail's last-run box and each *Earlier runs* row use it.
- **Where a task stands on the board:** `BoardDrive::column_holding(task) -> Option<&str>` gives the name of the column whose entry names the task. Done is not a column here, so a task in Done stands nowhere.
  - **Task detail:** the line of facts adds *On the board at <column>*.
  - **Tasks page:** a held task that is not at work has its `at` read *<said> · on the board at <column>*.
- **The project page's link:**
  - It reads *Board · N running · M to do*, then *· K waiting for you* when K > 0. The new part stands beside the rest, replacing nothing.
  - K counts the entries whose line offers an act (`board::line`'s second half: Start, or a person's move on).
  - The count comes from a core function, `board::line::waiting(board, facts)`, fed by the same facts the page uses.
- **The waits are not *Needs attention*:** they stay off the rail's count, as the proposal says. Nothing changes in `Task::group`.

- [ ] **Failing tests in `workflow/tests.rs`:**
