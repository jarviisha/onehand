# Board step 3: columns a person defines, in core — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A board's columns can be any number of person and workflow columns. Each has its own
*Starts*, *Moves on* and *Limit*. An issue moves through them on one task, with one run per
workflow column it enters. All of this is decided in core. Nothing a person sees changes yet:
step 4 builds Settings and step 5 the page.

**Architecture:** `board.toml` goes to version 3, whose shape is any list of columns. A look is
decided by a pure function, `board::flow::look`. It drops the closed issues, moves the ready
entries that move on by themselves, and starts the entries that wait in columns starting on
entry, within the team and each workflow's first-step room. `BoardDrive` writes the result and
holds its starts: `Start` for an issue with no task yet, `NextRun` for one with a task. Its
commands add, edit, remove and order columns, place an entry, and start on a press.
`TasksDrive::next_run` adds a run to an existing task. Each entry's line is worked out in core.

**Tech Stack:** Rust, serde + toml, GPUI in the app only.

**Spec:** `docs/superpowers/specs/2026-11-27-board-columns.md`, *Step 3*, *The model*, *The drive*.

## Global Constraints

- **Code rules:**
  - Core stays GUI-free.
  - No drive reads the clock or mints an id: column ids and task ids come from the carrier.
  - Our enums are matched whole.
  - Nothing in core is `pub` that nothing outside names.
  - No file past 800 lines of code. `board/drive.rs` is about 640 lines now: put new commands in `board/drive/columns.rs`.
  - No comment or string names a document.
- **File versions:** `SCHEMA_VERSION = 3`. Versions 1 and 2 are read; version 3 is always written.
- **Compatibility readers stay** until steps 4 and 5 replace them:
  - `Board::workflow()` returns the first workflow column's workflow.
  - `Board::todo()` returns the first column's issues that name no task.
  - `Board::work()` returns the entries of every workflow column, in column order.
- **Defaults:** a new column gets `Starts::OnEntry`, `MovesOn::ByItself` and no limit.
- **A start on a press goes ahead without waiting for the team:** the team caps only what the board starts by itself. The step room and the place still hold, as for any start.
- **Checks:** `cargo test --workspace --locked`, `make clippy CLIPPY_EXTRA="-- -D warnings"` and `make fmt`. Build output stays on `/data`.

## Review Focus

1. **The team and each workflow's first step are never overfilled.** This must hold when a single look both moves an entry into a workflow column and starts other entries there. The test is in Task 2.
2. **A moved entry never keeps its old column's state.** Moving clears `run` and `done`, so the entry is not taken as already started or done in its new column. The test is in Task 1.
3. **A person's move into a full column is refused,** and a move by itself waits in the column before. The test is in Task 2 (by itself) and Task 3 (a person's move).
4. **A run's end in a column the task has already left changes nothing.** This happens after a person moved the entry, then Retried, then the run ended. The test is in Task 3.
5. **An entry whose start was lost is never started again by itself.** It reads *Did not start* and waits for Start. The test is in Task 3.

### Task 2: `board::flow::look`, a look decided whole

**Files:**
- Create: `crates/core/src/board/flow.rs` and `crates/core/src/board/flow/tests.rs`.

**Interfaces:**
- Produces:
  - `pub(crate) struct Room { pub team: usize, pub first: HashMap<String, Option<(u32, usize)>> }`. `team` is the places left on the team. `first` maps a workflow id to its first step's limit and how many hold or wait there.
  - `pub(crate) struct Decided { pub board: Board, pub starts: Vec<Begin>, pub closing: Vec<u64> }`.
  - `pub(crate) enum Begin { New { issue: u64, column: usize }, Next { issue: u64, task: String, column: usize } }`.
  - `pub(crate) fn look(board: &Board, issues: &Issues, forge: Option<&'static dyn Connector>, room: Room, usable: &dyn Fn(&str) -> bool, now: u64) -> Decided`.

**Rules, in order:**
1. **Drop gone entries.** An entry with no task whose issue is closed or gone is dropped, wherever it is.
2. **Moves on, from the last column to the first.** An entry is *ready* in a person column, or in a workflow column when `done`. A ready entry in a `ByItself` column moves to the next column, or to Done after the last.
   - The next column must hold fewer than its limit.
   - When the next column is a workflow column starting on entry, the move needs an issue that is workable (when the entry has no task), a usable workflow, one team place, and that workflow's first-step room. The move then takes them, so the start that follows counts against them.
   - An entry that moves into Done is added to `closing`.
3. **Starts.** Each entry of a workflow column starting on entry, with `run == None` and no `done`, in column then entry order, starts while there is room as in rule 2. The entry must be workable when it has no task. The start is `Begin::New` without a task and `Begin::Next` with one.
- A column whose workflow is not usable starts and takes nothing.

- [ ] **Step 1: Write the failing tests.**
  - `the_migrated_shape_pulls_as_before`: To do `[4, 9, 11]`, team 2. Two `New` starts in order; To do is left with `[11]`.
  - `a_done_entry_moves_on_by_itself_and_its_next_run_starts`.
  - `a_ready_entry_waits_when_the_next_column_is_full`.
  - `a_move_and_a_start_share_the_team`: team 1, and an entry moving into a starting column. No second start.
  - `the_first_steps_room_is_per_workflow`.
  - `a_person_moves_on_column_keeps_its_entries`.
  - `entering_done_closes`.
  - `a_closed_issue_without_a_task_is_dropped_anywhere`.
  - `an_unusable_column_starts_nothing`.

### Task 3: `BoardDrive` on any columns

**Files:**

  - Create `crates/core/src/board/drive/columns.rs` and its tests.
  - The existing look and seen tests.

**Interfaces:**
- Consumes: Task 1's model, Task 2's `flow::look`.
- Produces:
  - **`Facts` changes:**
    - `template` becomes `templates: HashMap<String, Result<Template, String>>`, one per workflow column's id.
    - `first` becomes `first: HashMap<String, Option<Room>>`, from `task::rooms::Room`.
    - `ids` stays: a fresh id for each start the look may decide. The carrier gives `MOST_TEAM` ids, plus one more for each entry waiting in a column that starts on entry.
  - **New effect:** `Effect::NextRun { id, issue, task, run, template, column: String }`, answered by `Input::Landed`. `Effect::Start` gains `column: String`.
  - **`issues_read`** builds `flow::Room`, runs `flow::look`, and writes `Decided.board` with each start `begun` with its id. A new task's run id is its task id; a next run takes a fresh id. It holds the starts as now, and adds `Decided.closing` to `closing`.
  - **`ended`** acts only when an entry in a workflow column names the task. Done sets `ended_done`, then looks again.
  - **`tasks_read`** no longer drops an entry whose task is not there. That entry reads *Did not start*: the board keeps its `task` and `run`, and the look never starts it, because `run` is set.
  - **Commands:**
    - `add_column(&mut self, id: &ProjectId, column: Column, at: usize, valid: &dyn Fn(&Work) -> Result<(), String>) -> Result<Vec<Effect>, String>`.
    - `edit_column(&mut self, id, column_id: &str, edit: Column, valid) -> Result<…>`. The entries are kept; refused when the edit would leave run state in a person column while a run works there (see Rules).
    - `remove_column(&mut self, id, column_id) -> Result<…>`: refused while the column holds entries.
    - `move_column(&mut self, id, column_id, toward: Toward) -> Vec<Effect>`.
    - `place(&mut self, id, issue, to: Option<&str>, before: Option<u64>, working: bool, now) -> Result<Vec<Effect>, String>`. `to: None` means Done. It is refused while `working` ("It is at work: Stop it first") and refused into a full column ("<name> is full"). Into Done it closes. It then looks.
    - `start(&mut self, id, issue, ids: Vec<String>, template: Result<Template, String>) -> Result<Vec<Effect>, String>`. It works on an entry of a workflow column whose `run` is `None` or whose start was lost. It begins at once, held for its write.
  - `place_todo*`, `add_todo`, `drop_todo` and `move_todo` stay, as `place` on the first column.
  - Every change that changes which tasks are named says `Held`.

**Rules:**
- Turning a workflow column into a person column clears its entries' `run` and `done`. It is refused while one of them works ("Stop what works there first"). The carrier passes `working: &dyn Fn(&str) -> bool`.
