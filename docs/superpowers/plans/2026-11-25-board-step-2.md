# A project's board, step 2: a step's agent — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An agent step may name an agent of the agent list; that step runs in a session of its
own, opened on its first visit and kept for the rest of the run, so a developer step and a
reviewer step can be different agents.

**Architecture:** A run's sessions are **lanes**: the run's own lane (every step that names no
agent, as today) and one lane per step that names an agent. `RunDrive` keeps the per-session
state it already has (prompts sent, agent up, settings settled, pending prompt, card) per lane,
and works in one lane at a time, the current step's. Moving to a step whose lane has no session
yet asks the carrier to open one (a new effect); the carrier keeps one session per lane and hands
the drive the current lane's chat. Rules stay in `RunDrive`; the carrier only opens, subscribes
and routes.

**Tech Stack:** Rust, GPUI + gpui-component, serde/toml.

**Spec:** `docs/superpowers/specs/2026-11-24-board-design.md` (*A step's agent*)

## Decisions made here (the spec leaves them to the builder)

- **Lanes are keyed by step id.** `Lane::Run` | `Lane::Step(String)`. A step that names an agent
  is its own lane even when another step names the same agent.
- **Only the current lane is worked.** Events from another lane's session are ignored except a
  person's prompt there, which takes the whole run over (`Stop::TakenOver`), as in the run's own
  session today.
- **A lane's session lost while the run is elsewhere does not stop the run.** The lane forgets
  its session and opens a new one on its next visit (its context is lost, said in a note on the
  run: `The session of <step label> was gone; a new one was opened.`). Losing the current lane's
  session stops the run as today (`LinkLost`/`Closed`).
- **A step lane opens unshown** (in the rail, never taking the pane), whether the run is on
  screen or off. The run's first session opens as today.
- **The first session opened is the current step's lane**, so a run whose first step names an
  agent never opens an unused run session.
- **A step lane's mode is the step's own `mode`, else its agent's default.** The run's `mode`
  (`Setup.mode`) applies to the run lane only. A lane's baseline for agent settings (what a step
  not naming a setting goes back to) is what that lane's session had in force when it came up;
  it is not persisted (a Resume re-reads it from the new session).
- **Session names:** the run lane keeps the task's title; a step lane is `<task title> · <step label>`.
- **Stop** cancels the current lane's turn. **Close** (a done schedule or board task) closes
  every lane's session. **Drain** watches the current lane.
- **Schema:** a workflow file is written with `schema_version = 2` only when a step names an
  agent, else `1`; `store::parse` reads 1 and 2.

## Global Constraints

- Core stays GUI-free; rules in core; the app only carries effects out (`docs/drives.md`).
- Match our own enums exhaustively; no wildcard arms. Nothing in core `pub` unless named outside.
- Code comments never cite a document.
- Existing workflows (no step names an agent) behave exactly as before: one session, same
  names, same files (`schema_version = 1`). Every existing test passes unchanged.
- The step's key is `agent`, on agent steps only: `agent = "Codex"`. An empty value is a
  validation problem: `Name the agent, or leave the key out to use the run's.`
- Preflight finding for a step's agent that is not in the agent list (blocks):
  `<step label> names <agent>, which is not in the agent list.`
- A lane that cannot be opened fails the run at that step with:
  `The agent of <step label>, <agent>, did not start.` (resumable, like a session not started).
- Split a file past ~800 lines of code in the same PR (`workflow/run.rs` is at 797 and
  `shell/sessions.rs` at 795: add nothing to either; put new code in new files).
- `make fmt`, `make clippy CLIPPY_EXTRA="-- -D warnings"`, `cargo test` before each commit.
  Known: `onehand-issues` `only_the_newest_write_moves_the_selection` flakes on main too.

## Review Focus

1. **A step's agent removed from the agent list between start and its first visit** → the lane
   fails to open; the run ends failed with the lane's words and can be resumed once the agent is
   back. (Test in Task 4.)
2. **A person types into a step lane's session while another step runs** → the run is taken
   over, every lane becomes an ordinary session. (Test in Task 3.)
3. **A person closes a step lane's session while the run is at another step** → the run goes on;
   the next visit to that step opens a new session and notes it. (Test in Task 3.)
4. **A command step between two agent steps of different lanes** → no session is opened for it;
   the current lane is unchanged until the next agent step. (Test in Task 3.)
5. **Going back to an earlier step** (a failing command's `on_fail`, a person's *Revise*) →
   it runs in that step's lane's existing session, same uid, with its earlier context. (Test in
   Task 3.)

**Interfaces:**
- Consumes: `StepSpec::agent()`.
- Produces:
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq, Hash, PartialOrd, Ord)]
  pub enum Lane { Run, Step(String) }
  impl RunDrive {
      pub fn current_lane(&self) -> &Lane
      pub fn lanes(&self) -> impl Iterator<Item = &Lane>      // lanes that have a session
  }
  // Effect gains:
  OpenSession { lane: Lane, agent: String, name: String }
  // Input gains:
  LaneOpened { lane: Lane, result: Result<(), String> }
  LaneAppended { lane: Lane }          // something landed in a non-current lane's session
  LaneGone { lane: Lane }              // a non-current lane's session disconnected or closed
  ```
  `handle(input, chat)` and the other entry points keep taking `chat: Option<&Chat>`: it is always
  the **current** lane's chat. For `LaneAppended { lane }` the carrier passes that lane's chat
  instead, and the drive checks `prompted_beyond(lane.sent)` against it (take over).
- Rules:
  - Entering an agent step (`Action::Prompt`) whose lane differs from the current one: if the lane
    has a session, make it current and send; else emit `OpenSession` and keep the prompt pending
    in that lane until `LaneOpened(Ok)`. `LaneOpened(Err(_))` fails the run at the step with the
    words in Global Constraints, as `found_late(About::Agent)` does.
  - Command, approval and forge steps never change the current lane.
  - `came_up` per lane: the run lane sets `Setup.mode` as today; a step lane sets the step's `mode`
    if any; each lane captures its own settings baseline when it comes up.
  - `LaneGone` forgets that lane's session and adds the note in the decisions above on its next
    visit; it never stops the run.
  - The timeout, misses and visits are the run's, shared across lanes.
