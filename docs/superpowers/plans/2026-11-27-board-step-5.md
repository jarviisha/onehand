# Board step 5: the board page draws the columns — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The board page draws a board's own columns between the Backlog and Done, not the steps of one workflow. Each entry is a row with its line and, where it waits on a person, its one button. The moves sit in a row's `⋯` and are made by drag. A column's head says its limit and offers *Edit column…*; the page's head offers *Edit columns*.

**Architecture:**
- Every move goes through `BoardDrive::place`, `remove` and `start`, from step 3, carried by `crate::board`.
- What a row offers, and its line, are decided in core: `board::line` from step 3, plus a new `board::offers` for the moves.
- The page only draws, building `RowAct`s from what core answers.
- `board_page.rs` (804 lines) is split first.
- The step columns (`board::columns`, `task::board`, `StepColumn`) are removed.

**Tech Stack:** Rust, GPUI, gpui-component through `crate::controls` and `onehand_ui`.

**Spec:** `docs/superpowers/specs/2026-11-27-board-columns.md`, *Step 5*; the proposal's *The interface* › *A row*.

## Global Constraints

- **The `ui` skill governs every visible change.** Answer its *Finishing* path in the ledger. Follow `docs/ui-patterns.md` *Lists* (a waiting row keeps its act drawn as a button beside its `⋯`; `⋯` and right-click hold one list) and *Words*.
- **Rows** keep today's builder, `BoardPage::row`. It gains one drawn button for a row waiting on a person.
- **Columns** keep `board_page/column.rs`'s box at `COLUMN_W`. Each is capped at `BOARD_SHOWN`, with *N more not shown*.
- **Words** (core gives the line words, through `board::line`'s `words`):
  - A person's column's row reads `#N · <age>` (`onehand_core::age`).
  - A workflow column's row reads `board::line`'s words, or the task's own line (`task_line`) for `Line::Task`.
  - Drawn buttons: *Start*; *Move to <column>*; *Move to Done*.
  - `⋯` items, in order:
    1. *Show task* (with a task).
    2. The task's Tasks-page acts, but Dismiss.
    3. *Start*, when offered.
    4. *Move to <next>*; *Move back to <previous>*; *Move to Done*; then *Move to <column>* for each other column.
    5. *Move up* and *Move down* (within its column).
    6. *Back to Backlog* (no task) or *Remove from board* (with a task).
  - Moves refuse while its task works, with *It is at work: Stop it first*. The refusal is drawn as a refusing item, so the menu keeps its shape.
  - A column head reads `<name> · <n> of <limit>` with a limit, `<name>` without.
  - The head's `⋯` holds *Edit column…*.
  - The page's head line reads `<project> · team of N`, with *Edit columns* at its end.
  - Empty columns read *Nothing here*. The Backlog's line is as now, and Done reads *Nothing done yet*.
- **Drag:** every row drags but one whose task works. Dropping on a row lands just before it; on a column, last; on the Backlog, *Back to Backlog* / *Remove from board*; on Done, *Move to Done*. A drop that changes nothing writes nothing. A refused drop says why in a toast `failed("Moving #N", why)`.
- **Ids:** a start's ids come from the carrier.
- **Code rules:** no file past 800 lines of code; no comment or string names a document; no hard-coded colour or size.
- **Checks:** `cargo test --workspace --locked`, `make clippy CLIPPY_EXTRA="-- -D warnings"`, `make fmt`. No launching: the owner looks in `make dev`.

## Review Focus

1. **A row whose task works offers no move and does not drag.** A drag of it that does start is refused, said, and moves nothing. The test is in Task 2 (offers) and Task 4 (drag/refusal).
2. **The row's button and its `⋯` agree.** The drawn act is also the first act after *Show task*, so the keyboard reaches it. The test is in Task 2.
3. **A drop on the row an issue already stands before, or on its own column's end when it is last,** writes nothing. The test is in Task 4.
4. **A column whose workflow is gone:** its head says so, and *Start* refuses with why. The test is in Task 3.
5. **A board of eight columns in a narrow pane** scrolls sideways, each column at `COLUMN_W`. The strain tests already cover this; keep them passing.

### Task 2: What a row offers, in core

**Files:**
- Create: `crates/core/src/board/offers.rs` and its tests.

**Interfaces:**
- Produces:
  - `pub enum Offer { Start, MoveTo { column: Option<String>, name: String }, Up, Down, Back }`. `column: None` is Done; `Back` is the Backlog, or removal from the board.
  - `pub fn offers(board: &Board, issue: u64, working: bool) -> Vec<(Offer, Option<String>)>`, each paired with why it refuses, if it does.
    - Order: the line's act (`EntryAct`) first, then the moves in the Global Constraints' order.
    - Every move refuses while `working`.
    - `Up` refuses at the column's top and `Down` at its bottom.
    - `MoveTo` refuses for a full column, with *<name> is full*.
  - `impl Offer { pub fn words(&self, has_task: bool) -> String }` gives *Start*, *Move to <name>*, *Move back to <name>* (for the column before), *Move to Done*, *Move up*, *Move down*, *Back to Backlog* or *Remove from board*.

### Task 3: The page draws the board's columns and rows

**Files:**
- Modify: `crates/app/src/board_page.rs`, `crates/app/src/board_page/rows.rs` and `crates/app/src/board_page/column.rs`.
- Modify: `ColumnKey` gains `Board(String)` (the column's id), and loses `Todo`, `Step` and `Removed`.
- Create: `crates/app/src/board_page/moves.rs`, the presses below.

**Interfaces:**
- Produces:
  - `pub(crate) fn place(project: &ProjectId, issue: u64, to: Option<String>, before: Option<u64>, window, cx)` in `crates/app/src/board.rs`. It reads `working` from the entry's task, then calls `BoardDrive::place`. It carries the result, or toasts `failed("Moving #N", why)`.
  - `pub(crate) fn start(project, issue, window, cx)` in `crates/app/src/board.rs`. It takes the column's template, and works out `task_lost` (the entry names a task that is not kept). It passes fresh ids and calls `BoardDrive::start`. A refusal is toasted as `failed("Starting #N", why)`.
  - `pub(crate) fn column_head(column: &Column) -> String` in `board_page/column.rs`.
  - `BoardPageEvent::EditColumn { column: String }`. The shell answers it with `open_column_form(root, Some(column))`. *Edit columns* sends the existing `ProjectSettings`.
- **The page:**
  - Backlog: as now, but its drops come from every column.
  - Then each board column, in order. Its rows are the entries:
    - An entry with a kept task draws `task_row`, with its line from `board::line`. `run_here` means the task has a run with the entry's `run` id.
    - Any other entry draws `issue_row`.
    - The acts come from `board::offers`, plus the task's acts for a task row. The line's act is drawn as the row's button.
  - Then Done, from `board.done()`.
- **The row builder** `row(…)` gains `button: Option<RowAct>`, drawn before the hover slot as a `short()` secondary button.

  - `the_page_draws_the_boards_columns_in_order`: a board of To do, Plan (a workflow, starts on a press), Review (a person's) and Done. The test asserts each column's box selector, and the order by their `x`.
  - `a_row_waiting_for_start_draws_start`, by the selector `board-issue-4-button`.
  - `a_column_with_a_limit_says_how_full_it_is`: `column_head` words.

  - Keep the strain tests and the earlier row-words tests.

### Task 4: Drag between the columns

**Files:**
- Modify: `crates/app/src/board_page/moves.rs` and `crates/app/src/board_page/rows.rs`.
- Modify: `IssueDrag` becomes `EntryDrag { issue: u64 }`. The drop target says where it lands.

**Rules:**
- A row drags unless its task works.
- The drop targets:
  - A row lands the issue just before it: `place(to: that column, before: that issue)`.
  - A column's empty space lands it last: `place(to: that column, before: None)`.
  - The Backlog: `remove`.
  - Done: `place(to: None)`.
- A drop that changes nothing writes nothing. The drive's `edit` already writes nothing when the board is unchanged; the page does not check this itself.
- [ ] **Step 1: Write the failing tests**, on `crate::board::place` and `remove` through the rig:

  - `placing_an_issue_where_it_stands_writes_nothing`.
  - `a_refused_move_says_why` (a task at work; `task::hold_place`).
  - `dropping_on_the_backlog_takes_it_off_the_board`.
- [ ] **Steps 2–4:** Run the tests and expect them to fail. Implement. Run `cargo test -p onehand --locked board` and expect it to pass.
- [ ] **Step 5:** `git commit -m "feat(board): drag between the board's columns"`
