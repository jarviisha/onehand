# Board step 1: its drive and file — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move a project's board out of `project.toml` and `ProjectsDrive` into a file and a drive
of its own, with nothing new on screen.

**Architecture:** A `BoardDrive` in `crates/core/src/board/drive.rs`, held on `Shared`, owns every
board, kept in `projects/<id>/board.toml` in the column shape of the spec (To do, one work column,
Done), and written through `saving::Saves` as projects are. A blocking migration at boot moves the
old `board` key out of `project.toml`. The app's board carrier (`crates/app/src/board.rs`) only
carries effects and reports reads; the refusal rule it holds moves into the drive. What is on the
board stays derived from the tasks.

**Tech Stack:** Rust, serde + toml, GPUI in the app only.

**Spec:** `docs/superpowers/specs/2026-11-27-board-columns.md`, *Step 1*, *The model*, *The drive*.

## Global Constraints

- Core stays GUI-free: `cargo tree -p onehand-core -i gpui-pre` must still say "did not match any packages".
- No drive reads the clock or mints an id: `Now` and task ids come from the carrier.
- Our own enums are matched whole: no `_`, `matches!`, `if let` letting the rest through, in drives, links and their tests (`crates/app/src/guards.rs`).
- Nothing in core is `pub` that nothing outside it names; `#![warn(unreachable_pub)]` holds.
- No file past 800 lines of code (tests not counted); `project/drive.rs` is 798 now and only shrinks.
- No comment or string names a document.
- `schema_version = 1`, column ids `todo` and `work`; `DONE_KEPT` equals `BOARD_SHOWN` (50).
- Board files: `projects/<id>/board.toml`, written whole with `config::write_atomic`.
- Checks before the PR: `cargo test --workspace --locked`, `make clippy CLIPPY_EXTRA="-- -D warnings"`, `make fmt`.
- Build output goes to `/data`: `target/` is already a symlink there; a temporary worktree sets `CARGO_TARGET_DIR=/data/<name>-target`.

## Review Focus

1. A board file write that fails during the migration: `project.toml` must keep its `board` key, and a later project write (a rename) must still keep it. The test is in Task 2.
2. A `board.toml` with a newer `schema_version`, or one in a shape step 1 does not know: the board must say why, and no command may write over the file. The test is in Task 1 (the read) and Task 3 (no write).
3. A team track dragged and the app quit before its wait ran out: the last team must be written. The test is in Task 3 (`flush`) and Task 5 (the quit calls it).
4. A refused start whose task was already kept must not toast or put the issue back; one refused before it was kept must do both, once. The test is in Task 4.
5. *No board* on a board with tasks running: the file goes, and the running tasks run on. The test is in Task 3 (the delete) and Task 4 (an end after unbinding closes nothing and pulls nothing).

  - `pub struct Facts { pub template: Result<Template, String>, pub running: usize, pub extends_waiting: Vec<String>, pub first: Option<Room>, pub taken: HashSet<u64>, pub window: bool, pub ids: Vec<String> }`. These are reads of the tasks and the library, and `MOST_TEAM` fresh task ids.

  - New `Input`s:
    - `IssuesRead { id, read: Result<(Issues, Option<&'static dyn Connector>), String>, facts: Facts }`.
    - `Landed { id, issue: u64, task: String, kept: bool, result: Result<(), String> }`.
    - `Ended { id, issue: u64, outcome: Option<Outcome> }`.
  - `Signal::NotStarted { id, issue: u64, why: String }`.

Rules, each as today's `app/src/board.rs` and `ProjectsDrive::pull` hold them:
- **On `IssuesRead`,** the steps go in this order:
  1. `GivePlace` for each extend `extends_given` grants.
  2. With `Ok` read, a usable template and `window`: `pull`. Drop the `gone` issues from To do, and take out the `start` issues. Both changes go in **one** write.
  3. Add the started issues to `starting`, and give a `Start` per issue with the next id from `facts.ids`.
  4. With an `Err` read, do nothing beyond step 1.
- **On `Landed`:**
  - First take the issue out of `starting`.
  - `Ok`: `look` again.
  - `Err` with `kept`: nothing.
  - `Err` without `kept`: `Signal::NotStarted`, and nothing is pulled in its place.
- **On `Ended`:**
  - Done: remember the issue in `closing`, an in-memory set per project, and `ReadIssues`. On the next `IssuesRead` with `Ok`, `CloseIssue` for each remembered issue that `after_end(issue, synced, true)` allows; `synced` is `issues.in_step_with(forge.name())`.
  - `pulls_next(outcome)`: `look`.
  - A project with no board: nothing.
