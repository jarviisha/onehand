# A project's board, step 1: the board and its Backlog — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A project can bind a workflow as its board; the board shows Backlog (open issues), To do
(ordered), one column per step and Done; the person moves issues to To do and orders it; onehand
starts To do in order while fewer than the team size of the board's tasks are running, and again
after a restart.

**Architecture:** The board's settings and its To do live on the project (`project.toml`, owned
by `ProjectsDrive`). A board task is an ordinary task whose `Origin` is `Board`; it is made only
when pulled, through the off-screen start schedules and tools use. What to pull, what the Backlog
holds and which column a task stands in are pure functions in a new core module `board`; the app
carries them out. One agent per run, as today.

**Tech Stack:** Rust, GPUI + gpui-component, serde/toml/json.

**Spec:** `docs/superpowers/specs/2026-11-24-board-design.md`

## A deviation from the spec, decided here

The spec makes the task when the issue enters To do and leaves open "whether To do is *Queued*
with an order and a new reason, or a state of its own". This plan takes neither: **To do is a
list of issue numbers on the project's board settings, and the task is made when it is pulled.**
Why: a task made early needs a setup whose place is filled in at start, a kept-not-asking path in
`TasksDrive`, a new persisted state, and a new group on the Tasks page; all of it disappears if
nothing exists until the pull. Cost: To do items are not on the Tasks page (they are not work
yet), and a pull can still be refused by preflight, which is said in a toast. Task 1 updates the
spec's *To do and pulling* section to match.

## Global Constraints

- Core stays GUI-free and runtime-free: `cargo tree -p onehand-core -i gpui-pre` must error.
- Rules live in core; the app only carries effects out. No drive changes another drive's model:
  `ProjectsDrive` changes the board settings, `TasksDrive` the tasks.
- Nothing in core is `pub` unless something outside the crate names it.
- Match our own enums exhaustively; no wildcard arms (`crates/app/src/guards.rs`).
- Never call a board's item a *card* (glossary: a card is a parked permission or question).
- The bound workflow must have `place = "worktree"`; binding one that does not is refused with:
  `A board needs a workflow that works on a worktree: <name> works in the checkout.`
- Team size: an integer 1–8, default 2.
- Every list on the board is capped at `BOARD_SHOWN = 50` per column and says how many more it
  left out.
- A file past ~800 lines of code is split in the same PR (`crates/core/src/project/drive.rs` is at
  786 with tests in a file of their own).
- UI work follows the `ui` skill and its checklist; sizes in rems, colours from `cx.theme()`.
- Run `make fmt`, `make clippy CLIPPY_EXTRA="-- -D warnings"`, `cargo test` before each commit.

## Review Focus

1. **The bound workflow is deleted or becomes unreadable** → the board says so and pulls nothing;
   To do is kept. (Test in Task 2.)
2. **An issue in To do is closed or deleted elsewhere** (Issues mode, sync) → it is dropped from
   To do at the next pull rather than started. (Test in Task 2.)
3. **A pull is refused by preflight** (agent missing, dirty repo) → the issue goes back to the
   Backlog with a toast saying why, and the next one is not tried in a loop. (Test in Task 3.)
4. **Team size lowered while tasks run** → nothing is stopped; pulling resumes when the running
   count is below the new size. (Test in Task 2.)
5. **Restart with tasks in To do and a board task cut off** → To do pulls again; the cut-off task
   is under *Needs attention*, not counted as running. (Test in Task 3.)

### Task 2: What the board holds and what to pull

**Files:**
- Create: `crates/core/src/board.rs` (+ `crates/core/src/board/tests.rs`); add `pub mod board;` to
  `crates/core/src/lib.rs`
- Modify: `crates/core/src/task.rs` (`Origin::Board`, `Task::board_issue`)
- Modify: exhaustive `Origin` matches: `crates/core/src/task/tasks/ending.rs:87-90` and `:139-148`,
  `crates/core/src/task.rs:377-380` (`closes_session`), `crates/app/src/task/listing.rs:77-81`

**Interfaces:**
- Consumes: `Board` (Task 1); `Issues`, `LocalIssue` (`crates/core/src/issues.rs`); `Template`
  (`workflow/template.rs`, `steps: Vec<StepSpec>`, `place`); `Run::current()` (`run.rs:346`).
- Produces:
  ```rust
  // crates/core/src/task.rs
  Origin::Board { project: String /* ProjectId */, issue: u64 }
  pub fn board_issue(&self) -> Option<(&str, u64)>   // on Task: Some for a board task

  // crates/core/src/board.rs
  pub const BOARD_SHOWN: usize = 50;
  pub fn usable(template: Option<&Template>) -> Result<(), String>
  pub fn backlog<'a>(issues: &'a Issues, forge: Option<&'static dyn Connector>,
                     board: &Board, taken: &HashSet<u64>) -> Vec<&'a LocalIssue>
  pub fn pull(board: &Board, running: usize, open: &dyn Fn(u64) -> bool) -> Pull
  pub struct Pull { pub start: Vec<u64>, pub gone: Vec<u64> }
  pub fn columns<'a>(template: &Template, tasks: impl Iterator<Item = &'a Task>,
                     working: &dyn Fn(&str) -> Option<Working>) -> Columns<'a>
  pub struct Columns<'a> { pub steps: Vec<Column<'a>>, pub done: Vec<&'a Task> }
  pub struct Column<'a> { pub step: String, pub label: String, pub tasks: Vec<&'a Task> }
  ```
- Rules the functions carry:
  - `usable`: `None` → `Err("The board's workflow is gone or cannot be read.")`; a checkout place
    → the refusal in Global Constraints; else `Ok`.
  - `backlog`: open issues a brief can be made from (the filter of `supervised_brief_blocking`,
    `issues.rs:819-823`: `open && (synced || written_here)` — extract it as
    `pub(crate) fn workable(&self, issue, forge) -> bool` on `Issues` and call it from both), minus
    `board.todo`, minus `taken`; in `Issues::listed()` order.
  - `taken` (built by the caller): issues of board tasks of this project that are working, need
    attention, or are done.
  - `pull`: walk `board.todo` in order; an issue for which `open` is false goes in `gone`; the rest
    fill `start` up to `board.team.saturating_sub(running)`.
  - `columns`: one column per step of the template; a task stands in the column of its last run's
    current step; a task whose step is not in the template gets a column of its own after the
    others, labelled by its step id; a task whose outcome is `Done` goes in `done`, newest first; a
    task stopped by a person, taken over or dismissed is in no column.
  - `Origin::Board` matches: `not_started` treats it as a schedule's (fails unwatched, since nobody
    is looking); `let_go` emits the new `Signal::BoardEnded { project, issue, done: bool }`;
    `closes_session` as `Tool`; listing names its row *from the board*.

  `columns_place_by_current_step` (two steps, a task at each, a done one in `done`, a stopped one

  In `task/tasks/tests.rs`: `board_task_end_signals_board_ended` (done → `done: true`).

### Task 3: Pulling, in the app

**Files:**

  pull calls it with `Origin::Board`)
- Modify: `crates/app/src/task/place.rs` (carry `Signal::BoardEnded`)
- Modify: `crates/app/src/shell/boot.rs` (pull once tasks and projects are read)
- Test: `crates/app/src/board/tests.rs`

**Interfaces:**
- Consumes: `ProjectsDrive::{take_todo, drop_todo}`, `board::{usable, pull, backlog}`,
  `Origin::Board`, `Signal::BoardEnded` (Tasks 1–2); `start_task(window, shell, starting, cx)`
  (`control/start.rs:50-76`); `supervised_brief_blocking` (`issues.rs:812`); `windows::holding_root`;
  `onehand_issues::write(root, file, Change::SetOpen { number, open: false }, …)`.
- Produces: `pub(crate) fn pull_now(project: &ProjectId, cx: &mut App)` — called after any To do or
  team change (from the board page and settings), on `BoardEnded`, and at boot for every project
  with a board.
- Behaviour:
  - No window holds the project → nothing happens (it pulls when one of the three triggers comes
    next; `ponytail:` comment naming the missing trigger, a window opening, as the upgrade).
  - `running` = board tasks of the project whose `TasksDrive::working` is `Some`.
  - `gone` → `drop_todo` each. `start` → `take_todo(&start)` first, then for each, off the UI
    thread: the brief from `supervised_brief_blocking`, then `start_task` with
    `Starting { origin: Origin::Board { project, issue }, template: <bound>, brief, grant: default,
    agent: None, mode: None }`.
  - A refused start: a toast `Could not start #<n> from the board: <why>`; the issue is back in the
    Backlog because it is no longer in To do and no task links it. No retry.
  - `BoardEnded { done: true }` on an issue the project's own tracker keeps (not synced with a
    forge) → close it with `Change::SetOpen`. Then `pull_now`.
