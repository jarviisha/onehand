# A project's board, step 5: finishing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The person drags issues on the board (Backlog → To do at a place, reorder To do, To do →
Backlog) and opens the board's workflow, or one of its steps, in the editor straight from the
board. The work's spec and plans leave `docs/superpowers/`.

**Architecture:** Dragging is a pointer path over the same To do edits the row menus already make
(the menus stay, as the keyboard path); one new drive op places an issue at an index. Editing goes
through the Workflows page the app already has: the shell gains a way to open it on a workflow id
and a step, and a duplicate saved from a board's built-in workflow rebinds that board.

**Tech Stack:** Rust, GPUI + gpui-component.

**Spec:** `docs/superpowers/specs/2026-11-24-board-design.md` (*Steps of the work*, 5)

## Decisions made here

- **What drags:** an issue row of Backlog or To do. Task rows (step columns, Done) do not drag:
  moving a task between steps by hand stays a non-goal.
- **Where it drops:** on a To do row → the issue is placed before that row; on the To do column
  anywhere else → last; on the Backlog column → out of To do (as *Back to Backlog*). A drop of a
  Backlog issue on Backlog, or a To do issue on its own place, changes nothing.
- **Look:** the rail's drag ghost (moved to a shared place, not copied) shows the issue's title; a
  drop target fills with `hover_fill` as the rail's rows do. No insertion line is drawn (none
  exists in the app); the row it lands before is the one that fills.
- **The menus stay** (*Move to To do*, *Move up*, *Move down*, *Back to Backlog*), so the keyboard
  reaches every move.
- **Editing:** the board's head gets *Edit workflow* (a secondary button); a step column's head
  gets a ⋯ with *Edit step*. Both open the Workflows page on the board's workflow, the second with
  that step open. Settings ▸ Projects ▸ Board gets the same *Edit workflow* beside its picker.
- **A built-in workflow** opens read-only, with its existing *Duplicate to edit*. When the page was
  opened from a board and the duplicate is saved, that board is bound to the copy (team and To do
  kept), and a toast says `<project>'s board now uses <copy name>.` No other board changes.
- **A workflow that is gone** (bound id not in the library): *Edit workflow* is not drawn; the
  board already shows its refusal.

## Review Focus

1. **An issue dragged from Backlog onto a To do row** → it lands before that row, and the board
   pulls if there is room. (Task 1 core test; Task 2 wires it.)
2. **A To do issue dragged to its own place, or Backlog onto Backlog** → no write. (Task 1.)
3. **An issue closed while it is being dragged** → the drop still edits To do; the next pull drops
   it as closed, as today. (Task 1.)
4. **Duplicate of a built-in workflow saved from a board** → only that board is rebound. (Task 3.)
5. **A draft with unsaved changes open when *Edit workflow* is pressed** → the page's existing
   "unsaved changes" ask runs, nothing is lost. (Task 3.)
